A reviewable handoff, in three steps

Only carry what the next session needs.

Keep the summary small and explicit. Handoff Kit gives the next person or coding agent a portable starting point without trying to become an all-knowing memory system.

01

Write down the why

Capture the task, current state, decisions, verification, open questions, and the next concrete actions.

02

Attach what Git knows

Capture branch, commit, and changed file paths. Check later whether that snapshot still matches the checkout.

03

Export a plain file

Use Markdown for people and agents, or JSON for scripts. Review the contents before sharing.

Built to stay small

A handoff file, not another memory silo.

When work moves between tools, plain formats keep the handoff inspectable and easy to edit. The Git check adds a useful nudge when the saved snapshot has drifted.

01

Human-owned context

You write the summary and choose what belongs in it. There is no automatic transcript capture or model-generated account of the work.

02

Repository state alongside intent

Keep branch, commit, and changed-path metadata with the handoff. A CLI can flag when those saved values no longer match the current checkout.

03

Open, portable formats

Export ordinary .md and .json files. No vendor-specific memory format or hosted sync is part of this prototype.

Your repo stays yours

Small by design. Review before sharing.

The capture utility reads Git metadata—not source-file contents. The handoff remains a local file you can inspect and edit before it leaves your machine.

No chat logs, environment variables, or terminal history are collected by the prototype.
